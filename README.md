# Автопроверка документов — изображения и PDF

Графическая Windows-программа локально распознаёт опись, титулы и ИУЛ, сравнивает поля и создаёт HTML-отчёт со страницами, увеличенными фрагментами и результатами каждого чтения.

У приложения собственная иконка с документом, лупой и отметкой проверки. Она встроена в EXE в размерах от 16 до 256 пикселей и используется в окнах программы и на панели задач.

## Выбор страниц описи без повторного поиска — версия 1.8.0

После предварительного поиска открывается список всех фотографий и страниц PDF. Найденные страницы описи уже отмечены. Галочками можно добавить пропущенные страницы или снять ошибочные отметки; справа показана выбранная страница. Для нескольких страниц выделите строки и нажмите «Отметить выделенные» или «Снять с выделенных».

Окно ждёт решения пользователя и само не запускает проверку заново. «Начать проверку» продолжает текущий запуск с выбранной описью, уже подготовленными страницами и первичным OCR. «Продолжить позже», Escape и крестик оставляют запуск на паузе. Кнопка «Продолжить…» в основном окне возвращает к тому же выбору: PDF не открывается повторно, предварительное OCR не повторяется. Пока запуск на паузе, список входных файлов менять нельзя. Пауза сохраняется в текущем открытом приложении; после завершения приложения для продолжения потребуется новый запуск. «Отменить запуск» завершает текущий запуск явно.

Выбранные включения и исключения описи сохраняются в отчёте и учитываются при последующей повторной проверке. Опись можно указать отдельными фотографиями либо конкретными страницами общего PDF; делить PDF на отдельные файлы не требуется.

Номер изменения читается только из графы с заголовком «Номер последнего изменения». Подписные страницы без этой графы не участвуют в сравнении изменений; посторонние цифры, номер листа и номер разрешения не используются. При пересчёте старого отчёта ложные сохранённые значения на таких страницах удаляются. При извлечении названия книги отдельные строки OCR объединяются по координатам: слова одной физической строки читаются слева направо, даже если OCR вернул их в другом порядке.

## Шифры и повторная проверка — версия 1.7.1

Графа «Наименование и шифр объекта» в ИУЛ отделяется от обозначения документа. Следующие строки и соседние ячейки не объединяются со значением шифра.

Шифр рассматривается как значение графы документа или столбца описи. Для него не требуется префикс ИЛО, ТКР, фиксированная длина или определённый алфавит: поддерживаются буквенные, цифровые и смешанные значения, пробелы и знаки разделения. В описи границы столбца определяются по заголовкам и линиям таблицы, чтобы название документа не попадало в шифр. На титуле используется подписанное поле, характерная строка обозначения либо совпадение с шифром из описи. Произвольный текст без читаемого поля или однозначного соответствия может потребовать повторного OCR; программа не подставляет неизвестный шифр из похожей строки Excel.

При сопоставлении с Excel используются обнаруженные значения шифров и границы полного обозначения. Короткий код не совпадает с началом другого кода. Старые правила нормализации ИЛО и ТКР сохранены для совместимости с характерными ошибками OCR. Перенос кода и следующий заголовок читаются раздельно. Фрагменты одного тома с разными CRC32 заполняются отдельно; неоднозначные версии одного фрагмента остаются на проверку. Если сопоставленных строк нет, окно объясняет причину и не сообщает об успешном сопоставлении.

Чтобы повторить OCR отдельных страниц:

1. Нажмите **«Повторная проверка…»**. Откройте `Отчет.html` или `Результаты.json` предыдущего запуска. Если отчёт создан в текущем сеансе, он подставляется автоматически.
2. Отметьте нужные страницы. Можно выбрать все, снять выбор или отметить только опись. Двойной щелчок открывает сохранённое изображение.
3. Нажмите **«Повторить OCR»**. Программа повторно распознаёт сохранённые варианты только отмеченных страниц; остальные результаты OCR и детали использует из кэша. Затем пересчитывает общие сравнения, чтобы изменения выбранной страницы учитывались в других документах.

Для применения исправленных правил к старому отчёту без повторного распознавания включите **«Только пересчитать замечания по сохранённому OCR»**. Этот режим также восстанавливает ранее пропущенные шифры, если текст уже прочитан.

Сохраняйте всю папку отчёта вместе с `assets`: исходный PDF для повторной проверки не нужен. Результат записывается в новую папку, прежний отчёт сохраняется. После завершения доступно заполнение сводной таблицы. Новые чтения выбранных страниц заменяют их прежние результаты; старые фрагменты этих страниц удаляются только из новой копии, чтобы они не перекрывали новое OCR. Повторная проверка ограничена качеством сохранённых изображений: если в первом запуске использовалась маленькая фотография, для лучшего качества потребуется новый запуск с её оригиналом.

Пакетный режим: `--recheck <папка_старого_отчёта> <новая_папка> <Excel_или_-> ocr 1,3,5`. Для пересчёта без OCR: `--recheck <папка_старого_отчёта> <новая_папка> <Excel_или_-> cached -`.

## Запуск

1. Скачайте Windows ZIP из [Releases](https://github.com/debug23win/document-photo-audit/releases/latest), распакуйте и запустите `Автопроверка_документов.exe`. `Recognize.ps1` оставлен для совместимости со старыми обновлениями; приложение использует прямые API Windows.
2. Добавьте **JPG, JPEG, PNG, BMP, PDF**, папку или **ZIP с изображениями и PDF**. Поддерживаются многостраничные PDF; всего до 1000 страниц / изображений за запуск.
3. Для сверки CRC32 выберите Excel с листом `Все загруженные файлы`: C — имя файла, H — контрольная сумма.
4. При необходимости нажмите «Указать файл описи…» и выберите фотографии или PDF с описью. Страницы этих файлов предварительно отмечаются как опись; в следующем окне можно оставить только нужные страницы общего PDF. В списке файлов появится отметка `[Опись]`. Чтобы отменить назначение файла целиком, выделите его и нажмите «Снять отметку описи».
5. Выберите папку отчётов и нажмите «Проверить». После предварительного поиска отметьте страницы описи и нажмите «Начать проверку». Для паузы используйте «Продолжить позже»: возвращение через «Продолжить…» использует те же подготовленные страницы и первичное OCR. Каждый завершённый новый запуск создаёт отдельную папку. Кнопка «Открыть отчёт» открывает локальный HTML.

6. После завершения ответьте «Да» на вопрос «Заполнить сводную таблицу?». Введите фамилию, проверьте выбранный Excel и пункты отчёта, затем сохраните заполненную копию. Позже это окно доступно через «Заполнить свод…».

Требуются Windows 10/11, .NET Framework 4.8, русский компонент OCR Windows. Excel, Python и облачные API для работы не нужны. PDF преобразуется Windows.Data.Pdf в страницы с разрешением до 300 dpi, длинная сторона ограничена 5000 пикселями. Исходники не изменяются. Защищённый паролем PDF нужно предварительно сохранить в доступном для чтения виде.

## Заполнение по одной описи — версия 1.6.0

Для переноса данных загрузите только фотографии или PDF описи и файл проверки `.xlsx`. Excel можно добавить через «Добавить файлы», перетащить в окно или выбрать в строке «Файл проверки». При необходимости явно назначьте страницы кнопкой «Указать файл описи…». Если все загруженные страницы определены как опись, программа автоматически включает режим «только опись» и не создаёт замечаний об отсутствии титулов и ИУЛ.

После распознавания ответьте «Да» на предложение заполнить свод и введите фамилию. В окне показаны строки описи, распознанные значения и соответствующие номера строк Excel. Заполняются I «Проверил», J «Дата проверки», K «ДПТ / ИИ / ПД» и L «Короб». Флажок позволяет отключить перенос K/L. Вид документации читается из заголовка описи; на продолжение он переносится только при одинаковом явно прочитанном номере короба. Номер короба читается из своей графы, отдельно от изменения.

Прежние непустые K/L сохраняются. Если значение отличается от описи или не распознано, пояснение появляется в окне и в T «Примечание». Неоднозначные версии одного шифра с разными CRC32 пропускаются: одной описи недостаточно для выбора версии. В T также добавляется пометка, что сверена только опись и титулы, ИУЛ, подписи, печати и контрольные суммы по документам не проверялись. Это позволяет отличить частичное заполнение от полной проверки. Исходная таблица, прежние отметки и формулы сохраняются.

Перед обработкой оценивается свободное место: 8 МБ на страницу для рендеринга PDF, дополнительно 24 МБ на страницу для последующей обработки и резерв 64 МБ. Фактический размер зависит от изображений; наличие места проверяется также перед сохранением страниц. При нехватке места выводится понятное сообщение с предложением сменить папку отчётов, в том числе вместо общей ошибки GDI+ при сохранении изображения. Частичные файлы остаются в папке неудавшегося запуска.

## Заполнение сводной таблицы — версия 1.5.0

Предложение заполнить таблицу появляется только после успешной проверки, включая проверку без замечаний. При отказе Excel не создаётся. В окне заполнения нужны фамилия и файл `.xlsx` с основным листом `Все загруженные файлы`; по умолчанию используется выбранный реестр CRC32. Другую таблицу можно выбрать отдельно.

Строки сопоставляются по шифру документа. Если у одного шифра в Excel несколько версий с разными CRC32, программа выбирает единственную совпавшую с ИУЛ версию. Неоднозначные и отсутствующие строки перечисляются в окне и не заполняются. Остальные документы Excel остаются без изменений.

- I «Проверил» — введённая фамилия; прежние фамилии сохраняются, повторная не дублируется.
- J «Дата проверки» — дата завершения проверки, записанная как дата Excel.
- M — название тома/раздела; P — подписи и печать на титуле; Q — CRC32; R — подписи ИУЛ. В эти графы добавляется `1` для подтверждённых пунктов соответствующей категории.
- S — подтверждённые ошибки описи, включая несовпадение номера изменения.
- T — все пункты отчёта с пояснениями, включая сомнения OCR и общие замечания без шифра.

В списке «Подтверждено» заранее отмечены только пункты уровня «Расхождение». «Проверить» и «Наблюдение» сохраняются в примечании; просмотрев фотографию, можно подтвердить пункт и перенести отметку в профильную графу. Ошибки фамилий, непрочитанные поля и прочие пункты без отдельной графы остаются в примечании. Графа O о количестве страниц автоматически не заполняется: «Листов» игнорируется.

При полной проверке, если для документа нет пунктов отчёта, заполняются только фамилия и дата. Прежние отметки `1`, замечания, разметка, остальные листы и формулы сохраняются. Формулы статистики пересчитываются при открытии файла в Excel; значения статистики вручную не заменяются. Программа не создаёт формулы статистики для таблицы, в которой их нет. Если целевая ячейка содержит формулу или основной лист защищён, запись отменяется с пояснением.

Результат сохраняется в отдельный `.xlsx`: имя исходной таблицы выбрать нельзя. Для заполнения Excel не требуется. Пакетный запуск без интерфейса сохраняет отчёт и не задаёт вопросы.

## Фотографии описи — версия 1.4.0

Файл описи можно указать явно — это работает для отдельных фотографий и PDF, даже без распознанного заголовка. В версии 1.8.0 предварительное окно позволяет уточнить назначение каждой страницы PDF и показывает количество выбранных страниц до основной проверки.

Опись распознаётся и на странице с одной строкой, и на продолжении таблицы без слова «Опись». Если номер тома не прочитан или перенесён на две строки, строка извлекается по читаемому шифру в соседней графе. В отчёте есть отдельный раздел «Фотографии описи», счётчик страниц и ссылки от строк описи к исходным фотографиям.

Графа «Листов» игнорируется: её пустота, разные чтения и значения не создают замечаний и не используются для определения комплектности. Номер в графе «Лист» по-прежнему читается; сомнительное чтение сопровождается фрагментом для проверки.

По умолчанию включено «Ускорять уверенно прочитанные поля»: если как минимум два чтения целой страницы одинаково прочитали CRC32, номер листа или изменение и других прочитанных вариантов нет, увеличенные фрагменты этого поля не создаются. Пустые, одиночные и противоречивые чтения сохраняют обработку фрагментов. Подписные строки, печати, заголовки и фотографии описи проверяются полностью. Чтобы повторно читать все числовые поля, снимите флажок; для пакетного запуска используйте `--thorough`. Число полей, для которых удалось пропустить дополнительные фрагменты, сохраняется в `Время_проверки.json`.

## Очистка фото как у сканера — версия 1.3

Автоматически создаётся очищенная копия каждой страницы: оценивается цвет бумаги, плавно выравниваются тени и освещение, подавляется слабый шум фона и усиливается контраст текста. Цветные штрихи сохраняются; жёсткого перевода всего документа в чёрно-белое изображение нет.

Очищенная страница проходит дополнительное OCR. Чтения исходной страницы и фрагментов сохраняются для сравнения; очистка не подставляет ожидаемые значения из Excel. Увеличенные контрастные фрагменты тоже очищаются. Если очищенная страница даёт заметно больше распознанного текста и тот же шифр, она может использоваться для основного чтения. Конфликты чтений остаются видимыми.

В деталях каждой страницы отчёта доступны ссылки «Исходная фотография» и «Очищенная страница». Подписи и печати проверяются по цветному изображению после геометрического выравнивания, до очистки фона. Исходные файлы не изменяются. Обработка применяется также к страницам PDF; уже чистые страницы проходят тот же мягкий фильтр.

Очистка улучшает видимость бумаги и текста, но не восстанавливает детали, утраченные из-за бликов, размытия или обрезки. Дополнительный проход OCR увеличивает объём работы; параллельная обработка сохраняется. Старый кэш до версии 1.3 не используется для новых очищенных чтений.

## Параллельная обработка версии 1.2

В поле **«Потоки»** выберите «Авто» или 1–8. Авто учитывает процессор, доступную физическую память и размер страниц; число одновременно декодируемых больших изображений может быть меньше числа задач OCR. Даже ручной выбор ограничивается памятью и процессором. Режим 1 выполняет все этапы последовательно.

Параллельно выполняются подготовка и геометрия страниц, увеличение фрагментов, OCR целых страниц и фрагментов, рендеринг страниц PDF, анализ подписей и печатей, сохранение областей. Каждый поток имеет свои OCR-движки и изображения. Идентификаторы страниц и порядок отчёта сохраняются; сравнения между документами выполняются после завершения обработки всех страниц.

OCR и PDF вызываются напрямую из C# через Windows Runtime. Приложение не запускает PowerShell и не меняет политику выполнения. Убраны лишние полноразмерные буферы при выравнивании перспективы. Разрешение и количество повторных чтений сохранены.

Прогресс обновляется во время подготовки фрагментов. «Отмена» останавливает постановку новых задач и отменяет операции Windows; уже начатая обработка изображения завершается. После успешного запуска `Время_проверки.json` содержит общее время, время этапов и фактически выбранные ограничения параллелизма. Ошибки пакетного запуска записываются в `Ошибка.txt`.

Для сопоставимого замера используйте одинаковые исходники, пустые папки отчётов и последовательные запуски. Скорость зависит от памяти, нагрузки и размера страниц; число потоков не означает такое же ускорение.

## Пять улучшений версии 1.1

1. **Геометрия и мелкие поля.** При уверенном обнаружении границ листа исправляется перспектива, иначе наклон оценивается по текстовым строкам. Неуверенное выделение границ сохраняет исходную геометрию. Страница читается повторно в более высоком разрешении, затем CRC, изменение, номера листов, подписанты, блок согласования и заголовки — отдельными увеличенными фрагментами исходного разрешения. CRC сохраняется в PNG без потерь. Полноразмерный кэш — JPEG 100 без уменьшения, остальные крупные фрагменты — JPEG 99. Для второго чтения нормализуется контраст. CRC дополнительно читается английским OCR, если этот языковой компонент доступен; согласие двух чтений латинского фрагмента имеет приоритет перед общим русским чтением страницы, все альтернативы остаются в отчёте.
2. **Повторные чтения.** Все варианты сохраняются. Равенство голосов оставляет поле спорным; устойчивое большинство принимается с указанием альтернатив. Excel никогда не используется для подстановки ответа OCR. Число согласившихся проходов — показатель согласия, не вероятность правильности.
3. **Подписи и печать отдельно.** Строки выделяются по ролям; в ИУЛ дополнительно ищутся границы ячеек. Печатные слова и прямые линии удаляются из маски чёрных штрихов. Анализируются цветные и чёрные рукописные компоненты. Для титула отдельно ищется круговой контур печати. В отчёте доступны подписные области и их результаты.
4. **Разные формы документов.** Основной титул, титул фрагмента, основная страница ИУЛ, продолжение и опись обрабатываются раздельно. Главный инженер и ГИП — разные роли. Учитывается верхний блок согласования. Сравниваются роли и фамилии по организации, изменения, CRC, нумерация листов, книга и доступные полные заголовки раздела, подраздела и части.
5. **Измерение качества.** Кнопка «Сравнить версии» принимает два `Результаты.json` и необязательный ручной эталон. Отчёт показывает найденные ручные расхождения, ложные предупреждения на размеченных проверках, верные, неверные и нераспознанные поля. Без эталона показывается только покрытие. Формат: [tests/reference-format.md](tests/reference-format.md).

## Ограничения

Это поиск возможных ошибок с фрагментами для просмотра. Штрихи и круговой контур не подтверждают подлинность подписи или печати. Подписи, перекрытые печатью, блики, обрезка и нестандартные макеты могут требовать ручного просмотра. Поиск печати ориентирован на круглую форму; прямоугольные штампы автоматически не подтверждаются. Заголовки сравниваются по нормализованному тексту, без смысловой модели.

CRC сравнивается **по напечатанному тексту ИУЛ и Excel**. Хеш исходного PDF и его электронные подписи не проверяются: PDF может быть сканом или сборником документов.

Для переноса отчёта сохраняйте всю папку вместе с `assets`. Временный кэш `.ocr-work` удаляется после успешного завершения. Прерванный пакетный запуск в ту же папку может использовать кэш только при совпадении SHA-256 исходников. Храните отчёты отдельно от исходников.

## Обновления и конфиденциальность

При запуске автоматически проверяется стабильный Release. Ссылка «Установить v…» скачивает ZIP, проверяет SHA-256, создаёт резервные копии файлов программы и перезапускает её. Во время проверки обновление недоступно. Пользовательские данные не затрагиваются.

Интернет используется только для обновлений. Фотографии, PDF, OCR, Excel и отчёты никуда не отправляются. В публичном репозитории нет рабочих документов пользователей — только код и генераторы искусственных тестов.

## Разработка

C# 5, WinForms, .NET Framework, Windows.Media.Ocr и Windows.Data.Pdf. Для сборки нужен Windows 10/11 SDK с UnionMetadata; для запуска SDK не нужен. Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Version 1.5.0`.

Номера в нижнем штампе ИУЛ дополнительно читаются из отдельных цифровых ячеек. Если OCR пропустил одиночную цифру номера листа, программа сравнивает её форму с образцами нескольких шрифтов. Такое предварительное значение сопровождается отметкой «Предложено по форме цифры; проверьте фрагмент» и отдельным пунктом для просмотра. Оно не подставляется по порядку фотографий и не заменяет противоречащие друг другу чтения OCR. Непрочитанный номер не означает, что страница отсутствует: отчёт указывает неопределённость и показывает фрагменты для просмотра. Организация-разработчик определяется по шапке документа, а организация согласующего — по его отдельному блоку. Фамилия согласующего ограничивается этим блоком, чтобы название объекта не попадало в список подписантов. В сообщениях используются названия граф на русском языке; варианты OCR показываются только при наличии прочитанных значений.

Тесты: `tests/test_audit.ps1`, `tests/test_advanced.ps1`, `tests/test_pdf.ps1`, `tests/test_parallel.ps1`, `tests/test_updates.ps1`, `tests/test_summary.ps1`. GitHub Actions выполняет сборку и все тесты; тег `v1.2.3` выпускает Windows ZIP с контрольной суммой.

Независимый искусственный набор создаётся `python tests/generate_independent_fixture.py` (нужны Pillow и reportlab). Восемь страниц включают чёрные подписи, пустую ячейку, отсутствие печати, расхождения фамилий и книги. Этот тест не заменяет проверку на новых реальных комплектах.
