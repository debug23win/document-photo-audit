# Автопроверка документов — изображения и PDF

Графическая Windows-программа локально распознаёт опись, титулы и ИУЛ, сравнивает поля и создаёт HTML-отчёт со страницами, увеличенными фрагментами и результатами каждого чтения.

## Запуск

1. Скачайте Windows ZIP из [Releases](https://github.com/debug23win/document-photo-audit/releases/latest), распакуйте и запустите `Автопроверка_документов.exe`. `Recognize.ps1` оставлен для совместимости со старыми обновлениями; приложение использует прямые API Windows.
2. Добавьте **JPG, JPEG, PNG, BMP, PDF**, папку или **ZIP с изображениями и PDF**. Поддерживаются многостраничные PDF; всего до 1000 страниц / изображений за запуск.
3. Для сверки CRC32 выберите Excel с листом `Все загруженные файлы`: C — имя файла, H — контрольная сумма.
4. Выберите папку отчётов и нажмите «Проверить». Каждый запуск создаёт новую папку. Кнопка «Открыть отчёт» открывает локальный HTML.

Требуются Windows 10/11, .NET Framework 4.8, русский компонент OCR Windows. Excel, Python и облачные API для работы не нужны. PDF преобразуется Windows.Data.Pdf в страницы с разрешением до 300 dpi, длинная сторона ограничена 5000 пикселями. Исходники не изменяются. Защищённый паролем PDF нужно предварительно сохранить в доступном для чтения виде.

## Параллельная обработка версии 1.2

В поле **«Потоки»** выберите «Авто» или 1–8. Авто учитывает процессор, доступную физическую память и размер страниц; число одновременно декодируемых больших изображений может быть меньше числа задач OCR. Даже ручной выбор ограничивается памятью и процессором. Режим 1 выполняет все этапы последовательно.

Параллельно выполняются подготовка и геометрия страниц, увеличение фрагментов, OCR целых страниц и фрагментов, рендеринг страниц PDF, анализ подписей и печатей, сохранение областей. Каждый поток имеет свои OCR-движки и изображения. Идентификаторы страниц и порядок отчёта сохраняются; сравнения между документами выполняются после завершения обработки всех страниц.

OCR и PDF вызываются напрямую из C# через Windows Runtime. Приложение не запускает PowerShell и не меняет политику выполнения. Убраны лишние полноразмерные буферы при выравнивании перспективы. Разрешение и количество повторных чтений сохранены.

Прогресс обновляется во время подготовки фрагментов. «Отмена» останавливает постановку новых задач и отменяет операции Windows; уже начатая обработка изображения завершается. После успешного запуска `Время_проверки.json` содержит общее время, время этапов и фактически выбранные ограничения параллелизма. Ошибки пакетного запуска записываются в `Ошибка.txt`.

Для сопоставимого замера используйте одинаковые исходники, пустые папки отчётов и последовательные запуски. Скорость зависит от памяти, нагрузки и размера страниц; число потоков не означает такое же ускорение.

## Пять улучшений версии 1.1

1. **Геометрия и мелкие поля.** При уверенном обнаружении границ листа исправляется перспектива, иначе наклон оценивается по текстовым строкам. Неуверенное выделение границ сохраняет исходную геометрию. Страница читается повторно в более высоком разрешении, затем CRC, изменение, номера листов, подписанты, блок согласования и заголовки — отдельными увеличенными фрагментами исходного разрешения. CRC сохраняется в PNG без потерь. Полноразмерный кэш — JPEG 100 без уменьшения, остальные крупные фрагменты — JPEG 99. Для второго чтения нормализуется контраст. CRC дополнительно читается английским OCR, если этот языковой компонент доступен; согласие двух чтений латинского фрагмента имеет приоритет перед общим русским чтением страницы, все альтернативы остаются в отчёте.
2. **Повторные чтения.** Все варианты сохраняются. Равенство голосов оставляет поле спорным; устойчивое большинство принимается с указанием альтернатив. Excel никогда не используется для подстановки ответа OCR. Число согласившихся проходов — показатель согласия, не вероятность правильности.
3. **Подписи и печать отдельно.** Строки выделяются по ролям; в ИУЛ дополнительно ищутся границы ячеек. Печатные слова и прямые линии удаляются из маски чёрных штрихов. Анализируются цветные и чёрные рукописные компоненты. Для титула отдельно ищется круговой контур печати. В отчёте доступны подписные области и их результаты.
4. **Разные формы документов.** Основной титул, титул фрагмента, основная страница ИУЛ, продолжение и опись обрабатываются раздельно. Главный инженер и ГИП — разные роли. Учитывается верхний блок согласования. Сравниваются роли и фамилии по организации, изменения, CRC, нумерация листов, книга и доступные полные заголовки раздела, подраздела и части.
5. **Измерение качества.** Кнопка «Сравнить версии» принимает два `Результаты.json` и необязательный ручной эталон. Отчёт показывает найденные ручные расхождения, ложные предупреждения на размеченных проверках, верные, неверные и нераспознанные поля. Без эталона показывается только покрытие. Формат: [tests/reference-format.md](tests/reference-format.md).

## Ограничения

Это поиск возможных ошибок с фрагментами для просмотра. Штрихи и круговой контур не подтверждают подлинность подписи или печати. Подписи, перекрытые печатью, блики, обрезка и нестандартные макеты могут требовать ручного просмотра. Поиск печати ориентирован на круглую форму; прямоугольные штампы автоматически не подтверждаются. Заголовки сравниваются по нормализованному тексту, без смысловой модели.

CRC сравнивается **по напечатанному тексту ИУЛ и Excel**. Хеш исходного PDF и его электронные подписи не проверяются: PDF может быть сканом или сборником документов.

Для переноса отчёта сохраняйте всю папку вместе с `assets`. Временный кэш `.ocr-work` удаляется после успешного завершения. Прерванный пакетный запуск в ту же папку может использовать кэш только при совпадении SHA-256 исходников. Храните отчёты отдельно от исходников.

## Обновления и конфиденциальность

При запуске автоматически проверяется стабильный Release. Ссылка «Установить v…» скачивает ZIP, проверяет SHA-256, создаёт резервные копии файлов программы и перезапускает её. Во время проверки обновление недоступно. Пользовательские данные не затрагиваются.

Интернет используется только для обновлений. Фотографии, PDF, OCR, Excel и отчёты никуда не отправляются. В публичном репозитории нет рабочих документов пользователей — только код и генераторы искусственных тестов.

## Разработка

C# 5, WinForms, .NET Framework, Windows.Media.Ocr и Windows.Data.Pdf. Для сборки нужен Windows 10/11 SDK с UnionMetadata; для запуска SDK не нужен. Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Version 1.2.0`.

Тесты: `tests/test_audit.ps1`, `tests/test_advanced.ps1`, `tests/test_pdf.ps1`, `tests/test_parallel.ps1`, `tests/test_updates.ps1`. GitHub Actions выполняет сборку и все тесты; тег `v1.2.3` выпускает Windows ZIP с контрольной суммой.

Независимый искусственный набор создаётся `python tests/generate_independent_fixture.py` (нужны Pillow и reportlab). Восемь страниц включают чёрные подписи, пустую ячейку, отсутствие печати, расхождения фамилий и книги. Этот тест не заменяет проверку на новых реальных комплектах.

```powershell
./Автопроверка_документов.exe --batch --workers 0 C:\Reports\run C:\Data\registry.xlsx C:\Data\documents.pdf
./Автопроверка_документов.exe --compare C:\Reports\before\Результаты.json C:\Reports\after\Результаты.json C:\Reports\comparison.html C:\Reports\reference.json
```

Если защита Windows блокирует файл, сохраните сведения из журнала защиты и сообщите о срабатывании. Не добавляйте программу в исключения без расследования. Проверка подписи и сканирование конкретной сборки не гарантируют отсутствие обнаружений другими версиями защиты.
