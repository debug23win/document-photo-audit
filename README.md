# Автопроверка документов по фотографиям

Графическая Windows-программа распознаёт опись, титулы и ИУЛ, сравнивает поля и создаёт локальный HTML-отчёт с фотографиями и текстом OCR.

## Запуск

1. Скачайте `document-photo-audit-windows.zip` из [Releases](https://github.com/debug23win/document-photo-audit/releases/latest) и распакуйте в папку с разрешением записи.
2. Запустите `Автопроверка_документов.exe`. Файл `Recognize.ps1` должен оставаться рядом.
3. Добавьте изображения, папку или ZIP. Поддерживаются JPG, JPEG, PNG, BMP; до 1000 изображений за запуск.
4. Для проверки CRC32 выберите книгу Excel с листом `Все загруженные файлы` (C — имя файла, H — контрольная сумма).
5. Выберите папку отчётов и нажмите «Проверить». Каждый запуск создаёт отдельную подпапку. Кнопка «Открыть отчёт» открывает `Отчет.html` в браузере.

Требуются Windows 10/11, .NET Framework 4.8, штатный Windows PowerShell 5.1 и русский компонент распознавания текста Windows. Если русский OCR отсутствует, программа сообщит об этом. Установить его можно через параметры языка Windows. Excel, Python, платные API и доступ в Интернет для распознавания не требуются.

## Что проверяется

- Название книги в описи, на титуле и в ИУЛ, шифры и номера томов.
- Фамилия главного инженера на титуле и в ИУЛ соисполнителя.
- Номер последнего изменения в ИУЛ и изменение в описи; номер разрешения учитывается отдельно.
- Напечатанные CRC32 в ИУЛ и значения в Excel, различия CRC32 на страницах одного комплекта.
- Том из описи без фотографий, отсутствие основного титула, неполная распознанная нумерация ИУЛ.
- Предварительные признаки подписей и печати по синим отметкам; снимки с нераспознанным шифром.

Названия разделов сохраняются в полном тексте OCR. Автоматическое сравнение сейчас ориентировано на название книги; смысловое сравнение всех длинных формулировок разделов и частей требует просмотра.

Каждый пункт содержит снимки для подтверждения. Синий цвет — только признак рукописной отметки: программа не определяет подлинность подписи и не подтверждает отдельную печать независимо от подписей. Чёрная подпись, блики, поворот, обрезка и ошибки OCR могут дать ложное предупреждение. Отчёт предназначен для поиска **возможных** ошибок с последующим просмотром. CRC32 сравнивается по напечатанному тексту; хеш исходного PDF без самого PDF не вычисляется.

Лучшие результаты дают отдельные ровные снимки всей страницы, включая шифр, CRC32, таблицу подписей и номера листов. Программа выбирает ориентацию из двух вариантов; для страницы, снятой боком, сначала поворачивает её вертикально. Геометрические правила настроены на таблицы ИУЛ и описи с указанной структурой; другие макеты требуют доработки.

## Обновления

При запуске автоматически проверяется последний стабильный Release. Ссылка «Установить v…» скачивает пакет с GitHub, проверяет SHA-256 из API, создаёт резервные копии файлов программы и перезапускает её. Во время распознавания обновление недоступно. Рабочие данные не затрагиваются. Интернет используется только для обновления; фотографии, OCR и реестры никуда не отправляются.

## Разработка

C# 5, WinForms, .NET Framework, локальный Windows.Media.Ocr. Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Version 1.0.0`. `build.cmd` запускает сборку интерактивно. OCR-скрипт сохраняется в UTF-8 с BOM для PowerShell 5.1.

Проверки: `powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_audit.ps1` и `powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_updates.ps1`. Тесты используют искусственный текст и генерируемые изображения; реальных документов в репозитории нет.

GitHub Actions собирает и проверяет push. Новая версия выпускается тегом `v1.2.3` или опубликованным Release с таким тегом. ZIP автоматически прикрепляется к Release. Не публикуйте рабочие отчёты через эти репозитории.

## Конфиденциальность

Все изображения и OCR находятся только в выбранной локальной папке. Исходники не изменяются. В публичном репозитории и пакетах программы нет фотографий, рабочих Excel-книг или отчётов пользователей.
